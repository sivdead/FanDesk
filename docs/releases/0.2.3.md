FanDesk 0.2.3 减少温度监测、重复调速和窗口刷新带来的 CPU 开销，保留双风扇独立温控及安全恢复。

## 变化

- 常规硬件采样和遥测刷新调整为每 2 秒一次；心跳和状态查询复用最近读数，避免重复读取传感器和写入风扇目标。
- 隐藏、最小化或完全遮挡窗口后暂停遥测重绘；重新显示时立即刷新，菜单栏和温控继续运行。
- 复用菜单栏图标，跳过相同读数和状态的重复界面更新。
- 后台仍每秒检查控制会话、失联超时和系统热状态。失联超过 5 秒恢复系统自动控制；恢复失败继续重试。serious/critical 热状态保护绕过缓存。
- CPU 达到 90°C、选中温度达到曲线上限或传感器失效，在下一次硬件采样时处理；保护升速继续绕过平滑，转速上下限和签名权限检查保留。
- 补全后台服务启动参数，已在本机完成正式签名服务的注册与运行验证。

## CPU 与保护验证

通过 **115 项核心检查 + 38 项应用模型/启动检查，共 153 项**。

在 Apple M5 Pro（Mac17,8）、macOS 27.0.1 上，使用同一“CPU 温控 40–70”双风扇预设，窗口打开时前后各采样约 30 秒。平均 CPU 占用以单个逻辑核为 100%：

| 进程 | 优化前 | 优化后 |
| --- | ---: | ---: |
| FanDesk | 18.63% | 4.73% |
| FanDeskHelper | 1.35% | 0.43% |

两进程合计约下降 **74%**。关闭窗口后的另一次约 30 秒采样中，主程序为 **0.16%**、后台为 **0.46%**；关闭约 69 秒后仍读回双风扇温控生效。中断心跳后约 **5.65 秒**恢复系统自动；正常退出与重新启动恢复原预设也已验证，预设文件逐字节保持一致。

实机测量来自发布前的优化 build 6；0.2.3（build 7）重新构建并核对主程序、后台的可执行代码段一致，仅更新版本元数据及分发签名。以上是本机短时结果，不代表长期电量、声学或其他机型测试。高温保护使用模拟检查验证，未主动制造高温负载。

## 下载与升级

下载 **FanDesk-0.2.3-macos-arm64-notarized.dmg**。应用和 DMG 均使用 Developer ID 签名、通过 Apple 公证并附带离线凭证；Gatekeeper、应用分发检查和只读挂载检查通过。

首次安装将 FanDesk.app 拖入 Applications，再从“应用程序”打开，点击“启用风扇控制”并按 macOS 提示允许后台运行。

升级先恢复“全部自动”并退出旧版，在系统登录项中关闭 FanDesk 后台运行；将旧应用移到备份位置，再复制新版。重新开启后台运行并打开新版，必要时点击“启用风扇控制”刷新注册并完成 macOS 认证。升级保留已有预设和偏好。详见 [安装指南](https://github.com/sivdead/FanDesk/blob/v0.2.3/docs/installation.md)。

将 DMG 与 **SHA256SUMS-notarized.txt** 放在同一目录，运行 `shasum -a 256 -c SHA256SUMS-notarized.txt` 检查下载完整性。

支持 Apple Silicon（arm64）双风扇机型，最低构建目标 macOS 14；其他机型、旧系统、真实睡眠/唤醒和登录隐藏启动尚未完成验证。完整范围见 [验证记录](https://github.com/sivdead/FanDesk/blob/v0.2.3/docs/validation.md)。历史版本及其安装资产保留。
