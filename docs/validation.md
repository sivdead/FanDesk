# 测试与兼容性记录

记录日期：2026-10-18。实机：Apple M5 Pro（Mac17,8），macOS 27.0.1。

## 自动检查

0.2.0 公开分发构建通过 **78 项核心检查 + 33 项应用模型/启动检查，共 111 项**。

核心检查覆盖独立风扇模式、转速约束、温控曲线、传感器失效、心跳超时、自动恢复失败重试和预设迁移。应用模型检查覆盖持久化失败、过期异步回复、并发操作、睡眠/唤醒状态和登录启动事件。

公开分发版本额外检查非构建账户访问、活动用户切换、注销和无效用户身份，确保安装包不绑定构建者的 UID。运行入口为 `bash scripts/build.sh`。

模拟睡眠和登录事件证明对应代码路径，不代表真实系统流程已验收。

0.2.1（build 4）通过同样的 111 项检查，已安装到上述实机。点击关闭最后一个窗口后，系统记录的应用类型由 `Foreground` 变为 `UIElement`，进程和风扇控制继续运行；重新打开主窗口恢复 `Foreground`。主窗口与设置窗口同时打开时，关闭其中一个仍保留 Dock 图标，关闭最后一个才隐藏。预设及偏好设置逐字节保持一致，后台服务连接和已启用的登录启动均已回读确认。

系统应用类型通过 `lsappinfo` 读取；窗口关闭、重开及双窗口操作通过原生界面验证。真实注销后的隐藏启动仍待验证。

## 0.2.2 温控平滑

0.2.2（build 5）通过 **104 项核心检查 + 33 项应用模型/启动检查，共 137 项**。新增检查覆盖短时温度尖峰、持续升温、每秒 75 RPM 的缓慢降速、密集心跳与重复应用、传感器/曲线切换、固定和自动模式切回温控、两风扇独立状态，以及高温保护的立即升速和解除后的平缓回落。传感器丢失、心跳超时和原有恢复检查继续通过。

使用修改前采集的同一段 61 点真实温度序列回放控制引擎：仅增加平滑后，两侧目标转速累计变化量均减少 69.8%；再将 CPU 平均温度曲线由 40–65°C 调整为 40–75°C 后，分别减少 75.5% 和 76.4%。这是同输入下的算法回放结果，不代表声学测试或长期散热验收。

已完成本机安装、后台服务重新注册和签名连接验证。安装应用与通过检查的构建逐文件一致，新版后台以 root 身份运行。通过界面保存并应用双侧 CPU 平均温度 40–75°C 的“日常平稳”预设，原预设和全部偏好保持不变。

随后以约 1 秒间隔读取硬件，取得 121 个样本、覆盖 120 秒：两侧始终处于手动温控，18 项 CPU 温度读数齐全；CPU 平均温度 53.29–59.02°C，最高读数 69.38°C。左侧实际转速 2924–3334 RPM，右侧 3086–3545 RPM；相邻样本目标转速最大变化分别为 60/67 RPM，实际转速最大变化均为 62 RPM。该观察确认本机短期控制与平滑效果，不与不同负载时段直接比较降温或噪声效果。

高温保护通过模拟原始 CPU 最高温度达到 90°C、系统热状态 serious/critical 和选中温度达到曲线上限验证；未为本次修改主动制造高温负载。

## 开发构建 6：能耗优化（2026-10-17）

通过 **115 项核心检查 + 38 项应用模型/启动检查，共 153 项**。新增检查覆盖心跳复用读数、缓存期间的失联恢复和系统热状态保护、传感器失效后的缓存清除、自动恢复失败重试，以及隐藏窗口暂停遥测重绘、重新显示窗口读取最新状态。

在本机 Mac17,8、macOS 27.0.1 上，使用相同的“CPU 温控 40–70”双风扇预设，主窗口打开时前后各采样约 30 秒。以下为单个逻辑核的平均 CPU 百分比：

| 进程 | 优化前 build 5 | 优化后 build 6 |
| --- | ---: | ---: |
| FanDesk | 18.63% | 4.73% |
| FanDeskHelper | 1.35% | 0.43% |

主进程采用 `proc_pid_rusage` 的累积 CPU 时间差，并用 `mach_timebase_info` 换算时钟单位；root 后台进程采用 `ps` 的累积 CPU 时间差。关闭主窗口后，系统确认应用为 `UIElement`；另一个约 30 秒窗口内，主进程为 **0.16%**，后台为 **0.46%**。关闭窗口约 30 秒和 69 秒时，硬件回读均为双侧手动温控，18 项 CPU 温度读数齐全。

保持 XPC 连接、暂停主程序以中断心跳后，约 **5.65 秒**检测到两侧风扇恢复系统自动控制。随后恢复主程序并重新应用原预设。另行验证正常退出时两侧回到自动模式，重新启动后自动恢复原预设；预设文件与测试前备份逐字节一致。CPU 高温、曲线上限和系统热状态保护由上述自动检查验证。

本机应用已更新到 build 6，补全后台 `ProgramArguments` 并完成后台重新注册。主程序和后台均使用 Developer ID 签名，最终应用通过 Apple 公证、凭证附加和 Gatekeeper `Notarized Developer ID` 检查；主程序和后台可执行文件与构建输出逐字节一致。该轮本机验证尚未创建 GitHub 发布，也未修改公开的 0.2.2 安装资产。原始采样、硬件回读、保护验证和公证记录保存在本地 `build/energy-diagnostics-2026-10-17/`；以上是本机短时验证结果，0.2.3 分发检查另记于下文。

## 0.2.4 全速、心跳与固定转速界面修复（2026-10-18）

通过 **116 项核心检查 + 48 项应用模型/启动检查，共 164 项**。新增检查覆盖临时全速不制造未保存编辑、全速后切换已保存预设、主线程停顿超过 5 秒时继续发送心跳、睡眠和退出时停止心跳，以及失联恢复原因提示。

本机开发构建 8–10 完成对应实测：全速时双侧目标为硬件最高值 5349/5777 RPM，切换已保存预设不再误报未保存；预设和偏好文件与备份逐字节一致。固定转速编辑区的原始卡顿来自滑块以 1 RPM 为步进构造上千个刻度，调用栈反复进入 AppKit 的刻度布局。移除重复步进后，保留原有整数取整与精确输入；相同采样条件下，首次打开的操作及界面读回由约 10.0 秒降至 0.98 秒，采样中不再出现该刻度重建调用。上述耗时包含自动化操作与界面读回开销，不是纯渲染耗时。滑块拖动、两侧调整和精确输入 3001 RPM 均已验证。

心跳独立后，修复前同样会触发超时的约 6.2 秒界面卡顿不再中断风扇控制。另行暂停整个应用进程，约 4.13 秒后读回双侧系统自动；该时间取决于暂停前最后一次心跳时刻，后台的 5 秒阈值没有放宽。界面明确显示心跳中断原因。全部测试结束后恢复“CPU 温控 40–70”，未保留临时全速编辑。原始证据保存在本地 `build/shortcut-fix-2026-10-18/`、`build/heartbeat-fix-2026-10-18/` 和 `build/ui-stall-fix-2026-10-18/`。

随后从公开 DMG 升级本机至正式版 **0.2.4（build 11）**，确认主应用逐文件等同于包内输入、后台实际运行 build 11，原有 3 个预设和偏好文件逐字节一致。两轮“全部全速”分别持续约 18.1 秒和 27.8 秒，独立硬件探针取得 34/53 个稳定期样本，双侧均为手动模式且目标始终为硬件最高转速；全速后切回已有预设未出现保存提示。首次读取当前控制并打开固定转速编辑区连同界面读回约 0.80 秒，实际拖动连同读回约 0.66 秒；整数调节、精确输入 3001 RPM 和编辑不改变正在运行的控制均通过。

暂停正式版整个应用进程后约 3.53 秒读回双侧系统自动，恢复进程后界面显示心跳中断原因。该时长从暂停时刻计算，仍受暂停前最后一次心跳时刻影响。测试结束重新应用原“CPU 温控 40–70”预设，随后约 120 秒、61 个样本中双侧始终处于手动温控，目标均在硬件范围内；预设与偏好再次核对为逐字节一致。升级备份、界面记录与硬件读回保存在本地 `build/local-upgrade-0.2.4-2026-10-18/`。

以上为本机短时结果；真实睡眠/唤醒、其他机型与旧系统的边界仍按下文记录，不因本轮模型检查扩展验收范围。
